# OpenCode Handoff - 2026-10-24

## Verified Repository Context

`@myai-tech/studio` is the React/Vite administration frontend for myAI/Core. Its main use cases are first-run/bootstrap visibility, organization/user administration, persona creation/import, knowledge document operations, tool/runtime inspection, workflow management, audit, and realtime diagnostics.

Architecture:

- React 18 + TypeScript + Vite + Tailwind CSS 4.
- TanStack Query for server state and React Router for routing.
- `@myai-tech/myui` provides shared UI components.
- Handwritten Core API wrappers are under `src/lib/api/`.
- Auth tokens are persisted by `src/lib/auth-session.ts`; JWT tenant/org claims are interpreted by `src/lib/auth-context.ts`.
- Runtime configuration comes from `/runtime-config.js` and `window.__MYAI_CONFIG__`, with `VITE_MYAI_*` fallback.
- Container delivery uses a Bun build stage and nginx runtime (`Dockerfile`, `docker/`, `docker-compose.yml`).

## Current Objective And Progress

The active objective is to make Studio's session and organization behavior coherent with Core and `kairos-council`, then replace mock operational surfaces with supported Core endpoints.

Completed and verified in the current base commit:

- Protected application routes now use `requireAuth`.
- Bootstrap no longer reactivates merely because an org-scoped user query omits the global admin.
- Successful admin registration preserves the returned session rather than clearing it.
- Login performs a real backend organization context switch before persisting the selected workspace org.
- Safe auth reads (`/auth/me`, `/auth/context/switch`) can use refresh-and-retry; login/register/refresh/logout remain excluded.
- Workspace scope is constrained to JWT tenant/org claims.
- Shell org options are deduplicated, context changes invalidate active queries, logout clears cache/scope, and session loss redirects to login.
- Organization queries follow the active workspace/token org and refresh after switching.
- Organization user lists merge the current `/auth/me` user when an org-scoped list omits the global admin.
- Setup completion is based on tenant configuration, authenticated identity, and organization availability; realtime health and org-local user counts are operational signals, not bootstrap gates.
- Knowledge document IDs/search parameters are normalized to Core's current contract.
- Tools is now a read-only live screen using catalog/runtime/execution endpoints; unsupported management actions are not faked.
- Focused tests cover runtime config, token context, post-login session rollback, and knowledge org isolation.

## Decisions And Rationale

- **Token context is authoritative.** A local org selector must not send an org header that conflicts with JWT claims. This avoids mixed-token/mixed-header access after context switching.
- **Invalidate after context state changes instead of `queryClient.clear()` inside the switch mutation.** Clearing during the mutation can destroy unrelated cache state and allow observers closed over the old scope to behave unpredictably.
- **Bootstrap is tenant-level, not org-list-level.** A global admin may have `org_id: null`; org-scoped user counts therefore cannot prove whether initial setup exists.
- **Merge only the current global admin from `/auth/me`.** This fixes current-user visibility without pretending the org-scoped users endpoint is tenant-wide. Showing every global admin requires a Core tenant-directory contract.
- **Tools remains read-only.** The prior seeded management/approval UI implied unsupported capabilities. Live catalog/runtime/execution data is shown, while registration, secrets, approvals, and deletion remain explicitly unavailable.
- **Do not copy Council's session implementation wholesale.** Council has useful single-org/context-switch behavior, but its refresh path can retry with a captured stale token and can lose persisted tenant/org context. Studio retained request-time token lookup.
- **Rejected:** treating realtime connectivity as setup completion. It is health telemetry and can fail independently of bootstrap.
- **Rejected:** falling back to plausible mock data after API failures. Errors and unsupported capabilities must be visible.

## Outstanding Questions And Risks

- Core's org-scoped users endpoint does not provide a complete tenant-wide global-admin directory. Decide whether Core should add tenant-wide user/membership listing or Studio should label the view strictly org-scoped.
- Tenant/team choices in the shell need a clear authorization contract. Org switching has a backend endpoint; tenant context reset and cross-org team switching must not become local-header-only context changes.
- Multipart knowledge upload reads the current token but does not yet share the JSON client's one-time 401 refresh/retry path.
- WebSockets embed a token and need reconnect behavior when the token refreshes or org context changes.
- Several pages may still maintain initial token or page-local org snapshots (`Personas`, `RealtimeLab`, legacy persona creation, Audit). Audit all pages against the token-authoritative context rule.
- `Workflows.tsx` is still static. Core currently exposes `/v1/tools/workflows/scaffold`, but this generates a scaffold rather than a persisted workflow definition/execution lifecycle. Do not wire fake CRUD around it.
- The Core OpenAPI snapshot observed locally did not include every route present in Core source (for example some catalog/runtime/scaffold routes), indicating contract-generation drift.
- Bundle size is over Vite's 500 kB warning threshold; route-level code splitting is a later optimization.
- Tokens in `localStorage` remain pre-alpha security debt.
